# Native covariance-standardized satellite screening

This opt-in moving PPP policy uses native sigma 4 and
w_i=(S^-1 r)_i/sqrt((S^-1)_ii), S=H P H'+R. It is not raw r_i/sigma_i.
For diagonal R (as in this PPP path) this is the standardized post-fit
residual R S^-1 r, with covariance R S^-1 R. The low-level named kernel
retains its native formula for general supplied inverse operators.

`standardized_residual_gate_sigma` defaults to None and must be finite,
positive and used with ConstantVelocity or ConstantAcceleration. Test the
first linearization of each fresh proposed prior, before the existing NIS
gate. Remove the worst row's entire satellite (code, phase and ambiguity),
rebuild the remaining layout/prior/wind-up and retry from the last committed
state. Require at least the existing five code and four phase satellites;
otherwise reject the epoch. Every retry reapplies SPP/Doppler to a fresh
proposal, never to a previously velocity-fused or GNSS-updated proposal.
Existing nonlinear IEKF iterations and NIS/physical/postfit gates are unchanged.
Native commits one linearized update; Rust retains its nonlinear IEKF, a
separately declared algorithm difference. No native whole-PPP parity is claimed.

A rejected quality-screened satellite cannot survive optional continuous-arc
retention. Healthy retained arcs keep their last accepted data/time/count.
On overall success, only eligible phase arcs commit. Numeric mean, covariance
and state time remain transactional on all failure paths. Diagnostics retain
every selected row, signed statistic, remaining counts and whether removal
could proceed. Five code rows can still lack code redundancy for XYZ/clock/ZTD;
this screen is not a guarantee against weak geometry or source SPP outliers.

Independent native fixtures include 64 cases with the explicit inverse used
in upstream helper unit tests and 64 with production LDLT-to-identity solves.
Each actual helper is called, twice-generated bytes must match, decisions
must match exactly and all statistics retain the existing relative 1e-10
component bound. The original 64 explicit-inverse fixtures remain unchanged.
Rust also rebuilds each Gaussian S from independent P=.01 I, H=I, R=S-P,
checks SPD input covariance and tests all 128 statistics against native.
Boundary tests cover strict sigma equality, first-row ties, shared prior,
invalid inputs and non-mutation. Integration tests cover clean/noisy car
control equality, one/two corrupted code satellites, numeric equality with
independent omitted-satellite controls, ambiguity reacquisition, exhaustion,
retention exclusion and exactly-once velocity seeding after a screening retry.

An initial attempt treated the caller-supplied numerical inverse as a new
covariance, rejecting its floating asymmetry. The low-level native kernel now
checks shape/finiteness/positive diagonals and explicitly trusts that the
caller supplies S^-1; it does not certify SPD. Checked Gaussian construction
still validates actual P and R strictly with Cholesky, without loosening those
tests. Initial simple Cholesky solves also missed 1e-10 statistic parity on
an ill-conditioned shared-state case. Two compensated residual refinements
improve only the new screening solve; existing Kalman arithmetic is unchanged.
Both explicit-inverse and production-LDLT comparisons now pass the original
bound. Failed logs/source and a 90-decimal-digit oracle diagnostic are retained.

Before PPC execution, fix PVA, native head, IndependentEpoch clock,
InterruptAllArcs and the qualified GPS/Galileo SPP/Doppler seed mode.
Six cases x two IF pairs x off/native-sigma-4 = 24 runs / 234,536 rows.
All 12 off controls must match the previous 72 columns after only the already
audited clock-column/source label normalization. All source/input/binary
hashes are fixed before runs. Compare PPP and separate SPP fallback, both
reference origins and both Tokyo arms, common/new/lost successes and all
worst points. Existing noise/gates/phase calibration remain unchanged.
No threshold selection by truth, no reference/IMU fusion, no new whole-native
PPP calls and no practical runtime or performance acceptance are implied.
